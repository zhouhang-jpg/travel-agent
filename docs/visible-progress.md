# 用户可见的执行进展

助手执行期间会展示简短的进度说明和查询记录。进度说明用于告诉用户正在处理什么、
已有证据带来了哪些限制，以及下一步准备做什么；它是面向用户的沟通内容。
供应商要求回传的 `reasoning_content`、模型附加字段和完整工具结果继续保留在内部历史，
不会作为进度输出。

模型在继续调用工具的回复中，可以同时给出 `assistant.content`。运行器在确认回复完整、
工具调用结构有效且模型效果已提交后，将正文发布为 `commentary` 事件，再执行工具。
提示词鼓励有信息量的简短说明，但没有强制每次工具调用都发说明，也没有新增固定业务步骤。
直接回答和 `ask_user` 仍分别表示本轮交付和等待用户；进度说明不会自行完成或暂停运行。

本实现复用原本的模型请求，不增加专门生成进度的请求或工具。模型接口仍是非流式：
一次模型请求尚未返回时，页面显示真实的请求阶段与等待时间；正文在该轮返回后出现，
不是逐字输出，也不能保证按固定秒数生成新说明。

查询记录展示工具名称、选定的查询条件和排队、执行、成功、失败或复用状态。
条件摘要来自已知工具参数的允许字段，不公开完整参数 JSON、凭据或原始结果。
“成功”只说明工具完成了该次查询，不证明有票、有库存、价格完整或整个行程可行。
模型的进度正文仍受其理解与事实判断能力限制，不是独立验证过的结论。

默认 LangGraph 会话的公开事件具有稳定的效果标识和单调 `event_seq`，与已有运行围栏共用。
模型回复已提交后恢复运行可重发同一逻辑事件；事件键去重，避免重复进度。
会话快照的 `activity_events` 在同一个事件游标下重建全会话记录，按 `run_id` 对应各轮用户消息。
页面刷新、切换会话和完成回复后仍可查看，历史工具结果不重新执行。
旧记录只呈现原本已保存的事件，不补写当时没有生成的进度正文。

前端以事件顺序合并 SSE 和快照，避免重复事件或旧快照覆盖新进度。查询完成后的复用标记
不会把成功或失败退回执行中。legacy 可以实时发送进度说明，但不具备相同的持久化活动事件回放。
本次改动不增加执行中插话、取消、预订或支付能力。
