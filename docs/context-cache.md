# DeepSeek 完整上下文前缀缓存

日期：2026-10-10。上下文版本：`append-only-v1`。在阶段A正式提交`355923e`之后隔离开发，
保留其并发查询、逐项效果提交、原序工具历史、供应商限流和数据复用能力。

## 请求布局与准确性

过去每次模型请求都在第一条system消息中重写当前时钟、预算、行程及来源索引，随后才放
完整历史。长历史之前的一处变化会破坏先前请求的可复用前缀；固定微秒或每天的日期不能
解决预算、跨日、用户补充和行程变化。

现在默认Graph和legacy均发送：稳定行为策略、全部已有原始历史及旧system状态、最新
system运行状态增量。工具定义在运行初始化时按既有确定顺序冻结。先前请求中的每一条
消息和原始供应商附加字段保持原样，后续请求只在其后追加。不是临时把环境移到末尾又在
下次请求丢弃；发送过的状态本身也进入持久历史。

`runtime_context.py`定义系统状态协议。第一次快照包含时钟、时区、工具可用性和当前
行程/来源/原话索引；之后只追加发生变化的字段。时钟每次更新，跨日会更新日期及星期。
顶层按字段更新，planning按索引字段更新；字段内对象/数组整体替换，显式null可清空，
未提供字段沿用此前值。预算对象整体替换，新的用户轮次正确回到新run预算，而恢复旧run
继续使用其已提交请求次数及主动时间。运行时区不代表用户所在地。

快照使用真正的system角色，不假冒用户或工具结果。只有全部工具调用都有结果时才追加，
并校验历史不存在未闭合批次；不能插进assistant调用与tool结果之间。用户输入、助手
完整消息、完整工具结果及`reasoning_content`不裁剪、不摘要、不重建。`user_message_references`
和锁定/已订依据仍仅按role=user的真实Journal消息生成；公开事件与对话投影不包含快照
或私有推理。ReAct选择、追问协议、默认12次模型决策和300活动秒未改变。

## 持久化、退出与升级

Graph在预算预留之后、HTTP请求之前，通过同一owner/epoch围栏事务写入
`{model_effect_id}/context/{attempt}`。同一尝试的快照写入幂等；已完成模型效果恢复时直接
重放，不再生成快照或发起请求。状态刚保存但尚未发送、或模型返回却未提交时，仍保守
占用既有预算；恢复保留旧快照，新尝试再占用一次预算并追加新时钟和剩余次数。未知
完成不能算已知免费请求，也不能凭缓存观测宣称外部服务exactly-once。

并发工具仍先独立提交效果、再原序合并全部结果，之后模型节点才能追加状态。恢复中的
旧快照是历史，最新字段更新是当前值。legacy在每次发送前用原checkpoint钩子保存完整
历史；它仍不具备Graph的节点级恢复能力。

不需要表结构迁移：复用Journal与Effect的既有JSON字段。manifest加入上下文版本及
runtime_context源码指纹。部署变更时，已有进行中run遇到manifest变化按既有规则报告
`runtime_version_changed`，不默默改配置继续；历史保留，新的用户输入使用当前版本。
正常等待用户、完成或旧legacy历史无需改写，下一次运行开始追加新状态。策略、工具契约
或模型变化会使前缀缓存失效，属于必要的版本变化。其他模型厂商需核验其system顺序支持，
不能仅凭OpenAI兼容URL假定相同语义。

## 缓存观测与只读诊断

成功模型Effect保存原数值usage，并补充输入、命中、未命中、输出token、缓存一致性、
命中比率、模型参数、上下文版本、单次模型耗时和新增状态UTF-8字节数。恢复重放不会
创建另一份Effect或重复累加。字段缺失、不合法或hit+miss不等于prompt时，缓存比率保持
unknown；聚合报告每个字段的覆盖数。总量没有样本时为null。加权比率是
`sum(hit)/sum(prompt)`，仅使用有完整一致缓存计数的请求，不平均各请求百分比。

在仓库根目录运行：

```sh
uv run python -m scripts.report_context_cache --conversation-id <id> --output artifacts/cache-report.json
```

省略conversation-id时按配置数据库生成请求、run、会话和总体聚合。SQL只选择usage、
安全观测元数据和标识，不取用户正文、模型内容、推理或工具结果。SQLite以URI mode=ro
打开并启用query_only，不会创建不存在的库；PostgreSQL使用只读事务。不初始化schema
或恢复会话。未知结果尝试另列，无法知道其实际消耗；没有缓存字段的旧记录保持未知。
这衡量模型供应商的前缀缓存，和工具查询缓存完全不同。当前诊断针对Graph效果记录；
legacy只保存完整消息历史，没有等价的逐请求usage效果表。

## 真实六请求对照

可复现命令：

```sh
uv run python -m scripts.benchmark_context_cache_durable --live
```

会执行六次付费DeepSeek请求，无自动重试、预热或补请求刷命中率。每组使用独立SQLite库、
真实GraphRuntime和相同配置工具；合成工具实际读取本地八个候选，明确不是真实景点/
票价。每组先请求候选、根据真实本地工具返回答复，再接受新的用户输入要求说明费用缺口
及最新日期/时区/剩余请求次数。before仅把实际发给模型的上下文序列化还原为旧布局；
其他预算、持久化及工具路径相同。before库仍由当前Graph保存内部快照，所以on-wire
快照字节数和库内元数据含义不同，比较以捕获的实际出站请求和返回usage为准。

模型标识`deepseek-flash`，thinking=enabled，reasoning_effort=high；未传输出上限，
未切换系列或降低强度。请求之间人为等待3秒允许缓存构建，两组同样等待；下面耗时只含
实际模型HTTP调用，不含人为等待和存储。先before后after，首个请求已有账户缓存状态
未知，不能叫严格冷启动。完整合成历史和推理只留在忽略的artifacts库中，版本库只保存
[数值与协议核验记录](benchmarks/deepseek-context-cache-2026-10-10.json)。

同输入对照，也没有为此读取私人会话正文。

## 验收与限制

- 模型协议、Graph/legacy、API、行程版本/锁定/已订、并发原序、完整历史、大输入与大输出、
  时区/跨日、未知计数和幂等/围栏专项已通过。更新旧测试中依赖消息下标或旧system布局的
  断言，保留原有准确性与隐私检查，并新增精确前缀、状态更新和只读诊断验证。
- SQLite和真实PostgreSQL独立进程验证既有追问、接受答案、模型/工具/最终交付、预算及
  并行退出窗口；新增六项验证快照保存前后、已完成模型重放、原序工具合并后退出，确认
  旧前缀不变、预算不回退、重复请求不追加快照或重复计数。测试服务器独立于现有服务。
- 官方[缓存文档](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)于2026-10-10核验：
  默认开启、完整匹配已落盘前缀单元、秒级构建、尽力而为；不采用旧64-token块规则，
  不承诺固定90%或100%。带tools的完整reasoning回传依据
  [思考模式协议](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。
- 缓存比例提高不等于总成本必降。追加状态也会增加输入；报价按实际输入命中/未命中、
  输出和账户计价判断，本次未查询账单或承诺人民币成本。没有为了提高比例填充无用文本。
