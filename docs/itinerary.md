# 行程校验工具契约

`validate_itinerary` 是可直接运行的异步、纯本地工具：

```python
from travel_tools.itinerary import validate_itinerary
from travel_tools.schemas.itinerary import ValidateItineraryInput

request = ValidateItineraryInput.model_validate(
    {
        "planning_window": {
            "start": "2026-10-10T08:00:00+08:00",
            "end": "2026-10-10T18:00:00+08:00",
        },
        "items": [
            {
                "id": "walk",
                "title": "公园散步",
                "start": "2026-10-10T09:00:00+08:00",
                "end": "2026-10-10T10:00:00+08:00",
            }
        ],
    }
)
result = await validate_itinerary(request)
assert result.status == "unknown"
```

该例没有营业、固定安排、住宿、费用和预算范围的完整证据，因此不能通过整体验证。
工具不会请求模型、联网补证、询问用户或安排业务流程；它只检查调用者提供的安排和证据。

## 输入的准确含义

重复来源可在 `source_catalog` 中按 ID 定义一次，并在 `transfers`、`opening_hours`、`costs`
的条目中以 `source_ids` 引用，也可继续直接传 `sources`。已知证据仍必须有实际来源；不存在的
引用会被拒绝，解析后恢复完整来源，再执行原有校验。此机制只减少重复填写，不增加证据可信度。

- `planning_window`：本次安排的时间范围。`items` 是同一出行方需要实际占用的时间块，包含需要约束时间的活动、工作安排和交通等；住宿另用 `lodging`。
- 时间使用带 UTC 偏移的日期时间；比较和时间差按 UTC 绝对时刻进行。结束必须晚于开始。时间块采用半开区间 `[start, end)`，首尾相接不算重叠。
- `start_place_id` / `end_place_id`：时间块开始和结束所在地点的同一命名空间 ID。相邻块位置完全一致可确认零转场；缺失 ID 不表示相同地点。交通时间块可使用不同的起终点。
- `transfers`：从指定时间块结束到下一块开始所需的最小分钟数，可包含步行、候车等缓冲。已知数值必须带 `sources`。不同数值或未知证据并存时返回 `unknown`。只校验相邻时间块之间的衔接；起点到首项、末项到终点若需校验，必须显式表示为时间块。
- `opening_hours_required`：明确 `false` 且未提供营业证据时才视为不适用；缺失默认未知。若提供证据则检查证据。`opening_hours` 给出该访问的明确营业时间窗口、关闭或未知状态；已知状态必须有来源。
- `fixed_commitments`：固定时间和可选固定地点。时间块通过 `commitment_ids` 关联，单个关联时间块必须完整覆盖固定安排；有固定地点时起终点均需相符。只有 `fixed_commitments_complete=true` 才声明固定安排列表完整。
- `required_lodging_nights`：`null` 表示不清楚住宿需求；`[]` 明确表示不需要住宿。住宿夜用目的地当地的日期表示；酒店入住日包含、退房日不包含。可给出目的地 ID，不能把酒店 POI ID 当作目的地 ID。校验的是计划中有住宿安排，不能证明预订、库存、房型或入住资格。
- `costs[].total`：调用者已归一化为**全体出行人、全部适用房间和晚数**的该费用项总额，使用十进制金额。每人价、每间夜价格不得直接作为总额传入；无法得出总额应置空。已知金额需要来源、`reference` 或 `query_quote` 标记，以及独立的税费口径。
- `required_cost_ids`：完整的必需费用项 ID 集；`null` 代表费用范围未知。漏项、金额未知、税或附加费未完全包含时，费用覆盖是 `unknown`，不是零费用。所有已提供的费用都会计入总额，包括不在必需 ID 集中的项目。
- `budget_scope`：`limited` 必须附带预算金额和币种；`unlimited` 明确无预算上限；缺失为 `unknown`。预算也必须是同一全体出行范围的总额。不同币种不自动兑换。

所有 ID、引用、地点 ID、住宿目的地及酒店 ID 会先去除首尾空白，去除后必须是非空字符串。未知地点使用 `null`，不能使用空串或空白字符串；两个空白 ID 不能作为同地点转场、固定地点或住宿地点匹配的证据。输入 ID 在去除空白后必须唯一，转场/营业/固定安排引用必须存在。未识别字段、负金额、无穷数、无时区时间、倒置或空时间区间均被 Pydantic 拒绝。

## 输出与判定边界

每一项检查包含 `category`、`status`、`message`、相关 `item_ids`。状态是：

| 状态 | 含义 |
| --- | --- |
| `pass` | 对这一项，已提供的证据足够，安排符合证据 |
| `fail` | 已提供证据足以证明冲突 |
| `unknown` | 缺证、证据矛盾或范围不清，无法确认 |
| `not_applicable` | 根据显式输入，此项不适用 |

总体 `invalid` 表示至少一个 `fail`；否则只要存在 `unknown`，总体即为 `unknown`；全部检查均通过或不适用时才为 `valid`。空行程是未知。校验包含所有时间块的两两重叠，能够检测长事件包住多个短事件的冲突。

营业窗口连续相接时可以合并，但跨越午休等间隙不能通过。来源对该访问给出不同结论时为未知。同一住宿夜有多份计划住宿会失败。已知的同币种查询时报价小计超过预算，即使其他费用缺失也能确认超支；参考价超预算只报告“估算已超出”并保持未知。只有费用覆盖完整、全部为查询时报价、税和附加费全部包含、币种一致时才可能确认预算符合已提供报价。

输出 `known_cost_totals` 按币种分别汇总，不做汇率换算；`sources` 保留转场、营业和费用证据的来源、时间等共同字段。工具不验证来源真实性、时效、实际库存、天气安全或未来价格，也不判断输入是否完整反映了用户原始需求；调用者负责提供完整范围。输出明确保留这项限制。

## 验证方式

当前版本保存与局部修改复用此契约，扩展的protection、计价basis、buffers和交通块
travel_duration见[行程版本说明](itinerary-versions.md)。独立validator仍不联网验证来源；
保存层额外关联原始工具来源、有效期和适用条件，未知不会因此成为通过。

`tests/test_itinerary.py` 覆盖正常完整安排、稀疏输入、带不同时区偏移的相同时刻、嵌套重叠、转场不足或冲突、关门及营业窗口间隙、固定安排缺失/地点不符、住宿缺失/重叠/目的地未知、预算漏项/税费未知/参考价/多币种/确定超支、十进制与零金额、非法引用和非法区间。另有回归测试验证空白地点不能制造转场/固定安排/住宿通过，ID 去除首尾空白后再匹配和查重，`null` 地点保持未知。

这些是本地算法和契约验证，不代表任何外部地图、酒店、票务或报价供应商的真实联调。
