## 铁路重复查询

12306 独立浏览器取得的完整列表按真实 URL 缓存，时效和作用域来自当前 ToolSpec 的既有
配置。改变 max_results、train_numbers、席别等本地选择条件时，重新筛选完整快照，
不重新打开同一来源页面；改变实际发到站、日期、供应商配置或超出时效仍重新取数。
相同快照的并发查询共享一次取数。force_refresh 绕过两层缓存，缓存关闭时也不复用。
失败不会缓存成无票，失败刷新会清除旧快照，派生结果不重新延长原快照有效期。

同日候选优先排列尚未发车的车次，已经发车和时刻未知的候选仍保留；不隐藏无票或候补，
不推断有足够进站时间、不宣称可以买到。未来日期维持原顺序及筛选语义。
覆盖条数、来源时间、展示价、席别和库存含义不变。模型仍自主判断是否需要更多候选。

独立 Playwright 实查北京→石家庄、2026-10-10、单成人、city/12306：首查约 1.930 秒，
完整页面 44 行，先返回 3 项尚未发车的候选；随后 max_results=50 返回同一快照的全部
44 项，约 0.016 秒、coverage.cache_hit=true，data_time 与首查相同。此样本只说明本次
列表复用，不构成稳定网络速度、全市场覆盖或库存保证。

## JSON 语法错误与长保存参数

JSON 解析错误返回 json_error：source_call_id、message、line/column（一基）、
character_offset（零基 Unicode 字符，非字节）、character_count 和 at_end。
诊断不复制原参数、私有推理或堆栈。普通工具参数同样提供定位信息。

save_itinerary 在已有局部 patch 修正之外，支持 retry_from_call_id + argument_edits。
每次编辑指定 start/delete_count/expected/insert。服务只应用模型明确指定的编辑，
核实原文本匹配、不重叠、不越界，然后重新解析完整 JSON 并运行所有原有校验和保护。
不盲目补括号、猜报价、自动调整行程或放宽错误标准。

只允许本轮最近失败的保存。后一次失败若来自语法修正，服务从原始 journal 重放已有
明确编辑，再使用最新诊断位置继续修正。因此可逐个修复缺逗号和末尾缺括号，不需要
每次重新生成整份文档；无新表、无进程内候选缓存。位置匹配错误直接拒绝。
结构错误仍使用稳定条目 ID 的 patch；来源优先导入 available_source_ids，工具说明
建议省略默认可选字段和重复描述。原始坏 JSON 和每次编辑保持原样持久化并回传模型。

## 模型调用阶段

默认图运行持久发布 model_progress 的 running/complete/error 事件，关联请求序号、
尝试、开始时间与阶段。阶段来自最近的已提交工具结果，并在新用户输入后重新判断：
理解需求、分析查询结果、修正保存问题、整理已保存方案并准备答复。不会声称知道模型
下一步必然执行什么，不公开推理、原始参数或模型文本片段。

公共会话快照重建同一事件游标下的模型状态；SSE 重连与刷新不会遗漏正在执行的模型
调用。开始/完成事件按效果尝试幂等，已完成效果恢复不再请求模型。
前端展示本次等待秒数，并可展开此前查询/校验记录。秒数更新仅重新渲染进度标签，
不每秒重绘整份对话。模型仍为非流式请求；进度不代表已收到部分最终正文。
