# 多轮自主出行助手

用户可以先提出出行需求，Agent 自主决定回答、调用工具，或在关键信息缺失时询问用户。
`ask_user` 把控制权交还给用户；用户回答后，将新消息追加到同一会话，继续执行。
执行过程中不接收插话或用户中断。没有固定场景分类、工具调用顺序或要求填满的表单。

系统提示词只提供出行目标、自主决策说明、运行协议和必要事实边界，不规定先追问还是先查询、
问题内容与数量、工具组合顺序或最终回答模板。信息足够时可直接处理；不确定的需求也可先探索。
`ask_user` 仅规定模型选择等待用户时如何交还控制权，不规定模型必须在哪个业务阶段提问。
`ask_user.message` 必须非空，应用层不设置消息长度或问题数量上限。

提示词鼓励尽早识别会改变整体方案的缺失约束，并集中询问当前能够预见的相关问题，
以减少每次只问一点造成的返工。出发地、日期弹性、预算是否含交通住宿及总额/人均、
同行者需求、已定安排、兴趣节奏和出差可用时间只是按任务判断的维度，不是必填清单。
已有信息不重复问；用户让模型决定或尚不确定时可以提供选项、说明假设并继续探索。
信息充分时直接推进；可先查询候选/可行性再澄清，不强制先问后查。
选择等待回复时必须真正调用 ask_user，不能只在普通正文里写问题。

开放时间查询能力见 `opening-hours.md`。模型需要核对准确场馆、官方来源身份、规则有效期、
每周闭馆、停止售票/入园、临时及节假日调整和来源冲突，不能把地图原文或缺公告当成当日确认。

## 每次模型调用的上下文

- 版本化的系统行为策略，代码位于 `src/travel_agent/prompts.py`。
- 本轮请求的当前时间、指定时区和工具可用状态；默认时区为 `Asia/Shanghai`。
- 完整的用户、assistant 和 tool 历史，包括原始工具调用、完整工具 JSON 结果及供应商要求的
  `reasoning_content`。这些附加字段只供模型协议和内部持久化使用，不发送至用户事件流。
- 实际可用的函数定义，另加 `ask_user`。当前从定义、运行环境目录和运行时分发三处排除长途大巴票查询。

已有 `fetch_webpage` 可按需要读取公开网页；本期跳过的是大巴票及其爬虫接入。

系统消息不存进会话历史，每次请求重新生成运行环境。历史不摘要、不裁剪、不检索替换；
不创建、注入或更新长期用户档案。用户在当前会话表达的偏好仍是规划依据。
新产生的成功工具结果采用 `travel-table-v1` 无损表示（仅在字符量更小时使用）：
重复记录以 `common`、`fields`、`$rows` 表达，`count` 明示实际条数；相同的长对象或字符串
可用 `$ref` 引用本条结果的 `shared` 值。`order` 保留原始字段顺序，`$json` 展示原来嵌入
字符串的 JSON 内容。全部记录、步骤、空值、来源、时间、限制和未知状态均可精确解码恢复。
这是工具结果产生时的表示，不是历史摘要或删减；旧历史保持原样，新结果按同一表示保存和回传。
HTTP 工具 API 仍返回原有结构。模型输入 Schema 只去掉显示用 `title`，所有参数、约束、
默认值和说明保留；字段本身名为 `title` 时仍完整提供。
不设置应用层上下文字符数上限，系统消息、完整历史与工具定义直接交给模型服务。
不传输出 token 上限参数，不限制模型响应字节数。模型服务自身容量与默认输出策略仍然适用；
供应商截断或拒绝会明确报错，不静默删除消息，也不把不完整输出交付成成功方案。

## 状态与事件

`AgentRunner.run(history, emit, timezone_name=...)` 返回 `RunOutcome`：

- `completed`：模型交付当前请求的最终回答。
- `waiting_user`：有效且独立的 `ask_user` 已写入调用与对应结果，等待下一条用户消息。
- `error`：资源上限、模型异常、超时或意外中断，包含安全的错误码与中文说明。

`history` 返回包含原消息的完整副本。公开事件只包含回答/问题，以及工具名称与执行状态；
不包含原始工具参数、工具结果、凭据和隐藏推理。服务层应持久化内部历史并限制其访问。
可通过 `checkpoint` 异步回调在每条 assistant/tool 消息产生后保存完整内部历史；该回调
只供服务层持久化，不进入 SSE。进程退出后可以根据最近一次成功的检查点恢复。

如果 `ask_user` 与其他工具同时调用，整组调用全部返回明确错误，任何一个工具均不执行，
模型可在下一轮修正。未知工具和无效 JSON 同样作为工具错误反馈给模型，而不是模拟成功。

每条 assistant 工具调用都有匹配的 tool 结果。运行限制或中断发生在一批调用中间时，
尚未完成的调用写入错误结果。服务重启时可调用 `repair_history(history)` 为没有结果的调用
补充 `interrupted`，保留原始消息和已完成结果，且不会再次执行工具。

## 资源与准确性边界

默认一次运行最多12轮模型决策、24次工具调用、300秒；单次模型请求120秒。
上下文与模型输出没有应用层长度上限。
模型错误不自动重试；模型返回截断、内容过滤等非正常结束不能当作成功答案。
工具错误允许模型自主选择有价值的修正方式，但仍受统一预算约束。

FlyAI 的单成人、单房间及报价不完整限制必须反映在方案中；单人价格不能冒充多人报价，
房型、税费和库存未知时保持未知。网页只是证据，不能覆盖系统规则或驱动越权操作。
工具只读，不支持预订、支付或取消。最终回答按当前请求给出相关行程、交通住宿建议、
费用口径、来源、假设和未知项，不强制无关字段。
