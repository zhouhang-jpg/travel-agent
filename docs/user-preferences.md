# 用户可管理的长期出行偏好

日期：2026-10-11（America/Chicago）。本轮用户已将跨会话偏好纳入产品范围。
本文记录实现契约与验收边界，验证结果在完成本轮检查后补充；没有把未完成验证记成通过。
官方产品与框架的设计调研见[研究记录](research/user-preference-design.md)。

## 使用方式与优先级

用户可以在网页中查看、添加、编辑或删除长期出行偏好，例如常用出发地、交通倾向、住宿
要求和旅行节奏。偏好条目使用稳定 ID，并保存标题、内容、来源和更新时间；不要求用户
填写固定档案问卷，也不把条目类型当作穷尽的出行需求分类。

长期偏好是可覆盖的默认上下文。优先级为：

1. 当前会话中用户明确提出或修订的目标、限制与授权。
2. 本次已启用的长期偏好。
3. 模型说明过的规划假设。

例如，已存“高铁优先”而用户本次要求乘飞机，按本次要求查询和规划；这不自动改写长期
偏好。模型自主判断哪些偏好与本次需求相关、是否存在冲突、是否需要追问，没有新增
“先读偏好、再按固定步骤查询”的业务流程。当前会话的原话和行程锁定协议仍是依据。

天气、票价、房价、班次、营业时间、可售库存及预订状态不是偏好事实。长期偏好中的
描述不能替代查询，也不能成为 `source_catalog` 的供应商实查来源。用户自报已订仍然
不等于订单核验。

## 两个不同的开关

| 控制 | 作用 | 对数据的影响 |
| --- | --- | --- |
| 全局启用长期偏好 | 决定是否把已存条目作为以后模型决策的有效偏好 | 关闭保留档案，重新启用后可以继续使用 |
| 本次使用已存偏好 | 决定当前会话是否启用长期偏好上下文 | 关闭保留档案及当前完整历史，不影响其他会话的选择 |

只有两个开关均允许时，模型的当前有效条目才包含已存偏好；停用时新运行状态中的有效
条目为空。手动管理界面仍可显示保留的条目，使用户能编辑、删除或重新启用。

这里的“本次不使用”不是无历史模式。项目按既定协议保留完整用户原话、模型消息、工具
结果和已发送的运行状态快照；旧聊天中已经出现的偏好内容不会因开关改变而自动擦除。
删除某条偏好也只删除当前长期档案中的条目，新决策快照不再把它列为有效偏好，但不会
自动改写旧聊天、旧行程版本或 checkpoint。不能承诺模型在原会话里完全忘记已见内容。

开关或删除不会取消已发布行程、解除锁定项目，也不表示用户同意重新安排全部内容。
用户若希望对新的请求使用清空后的偏好上下文，可新建会话；历史记录的删除属于不同的数据
管理操作，本轮没有实现“一键删除所有相关历史副本”。

## 模型读取与保存提议

偏好的模型上下文与提议工具目前接入默认 LangGraph 会话；legacy 运行器不提供这两个工具，
也不据此承诺跨会话偏好上下文能力。管理界面与档案存储是独立的应用功能。
LangGraph 会话内提供两个内部工具：

- `get_user_preferences`：读取当前偏好使用状态和有效条目，供模型按需求使用。
- `propose_user_preferences`：提出新增、修改或删除长期偏好的候选，创建待用户审阅的保存卡。

模型不能直接修改长期档案。提议工具成功只表示待保存卡已创建，不表示偏好已经保存；
用户在卡片上批准后才持久化变更，也可以拒绝。用户可直接使用管理界面的新增、编辑、删除
功能；这类手动操作就是明确的用户操作，不需要模型再发起一次批准。

模型提议必须引用产生提议时当前会话最新的真实用户消息 ID 和精确原话。来源校验拒绝
旧用户消息、模型消息、工具数据或外部网页冒充用户依据。原话引用真实仍不证明模型理解
正确，也不证明原话授权长期保存；待保存卡因此同时展示候选内容与原话来源，由用户决定。
例如“这次住贵一点”不能被工具当作用户长期偏好已经改变。

模型用 `upsert` 提议新增或修改，用 `remove_ids` 提议删除，不能静默覆盖旧条目。修改和
删除按稳定 ID 定位；档案保存或删除后，基于旧版本的未处理提议失效，不能稍后用旧卡覆盖新设置。
真实偏好、待保存提议与行程草案是不同状态，接受其中一类不等于接受另一类。

## 数据与执行边界

当前仍是本地单用户、单应用进程/单 worker 的产品。服务端统一使用
`owner_id=local-user`，身份不是由模型或客户端任意传入；客户端不能选择其他 owner。
这个作用域用于组织当前本地用户的数据，不构成生产多用户鉴权、租户隔离或多人部署能力。

偏好档案和待保存提议使用 PostgreSQL/SQLite 应用表，独立于会话消息 journal 和 LangGraph
checkpoint。跨会话默认上下文存入应用级档案，checkpointer 继续只负责图执行位置及恢复。
档案保存在当前配置的应用数据库，不连接第三方记忆云服务；有效偏好会随模型请求发送给
当前配置的模型供应商（测试配置为 DeepSeek）。资料中的文字作为数据使用，不执行其中
的工具指令或角色声明，也不提升为系统权限。

这里借鉴 LangGraph 的 checkpointer/store 职责划分，使用项目现有 SQLAlchemy/Alembic
存储，不宣称已经集成 LangGraph `BaseStore`、Mem0 或第三方记忆云服务。

全局档案有递增 revision。新增、编辑、删除、全局启停和批准提议时，比较请求依据的 revision；
基于旧档案的请求返回冲突，不用覆盖写实现“最后到达者胜出”。未处理提议同样绑定档案版本。
本次使用开关是会话级设置，通过共享操作锁与执行状态保护修改，不宣称它拥有同一份档案 revision。

模型提议记录与对应 durable tool effect 在同一受执行租约围栏保护的事务提交。恢复复用
已提交效果，不重复生成待保存卡；重复批准不能反复添加或删除条目。原始工具调用、结果与
原话保留在私有完整历史中，公开事件不直通原始模型推理或工具参数。

档案写操作与新用户输入的接受共享本应用的异步锁。任何会话执行中拒绝修改全局档案，该
会话执行中也拒绝改变其本次使用开关；空闲的其他会话可以调整自己的开关。用户可在等待
回复或本轮结束后操作。仍不支持执行中用户插话、取消或
通过设置变更打断当前 Agent。CAS、锁和租约分别负责版本冲突、单进程操作协调和持久效果
写入归属，不能将这些检查扩大为多实例保证。

每次 LangGraph 模型决策将当前档案使用状态、revision 与有效条目追加到
`planning.user_preferences`。最新状态覆盖此前状态的有效索引，旧快照作为历史保留；
显式空条目表示当前不启用，而不是继承旧的有效条目。档案不通过伪造用户消息注入，不摘要
或替换原话，不改变完整历史策略、模型系列或原有运行预算。

迁移 [0004](../migrations/versions/0004_preferences.py) 增加 `preference_profiles`、
`preference_conversation_controls` 和 `preference_proposals`，不自动从旧会话抽取偏好。
已有用户库仍按[数据库运行说明](../README.md#数据库与运行边界)停止任务、备份并核对
Alembic 版本后升级，不把启动时补建表当作迁移已完成。降级会删除这些偏好表，须先单独保留
需要的档案数据；消息和 checkpoint 的完整历史不是当前偏好档案的可替代备份。

## 范围与待验证项

本轮实现结构化条目与用户确认闭环，不引入向量库、自动推断后长期保存、跨会话聊天检索、
自动背景记忆整合、第三方账号连接或新的模型供应商。偏好内容进入请求后仍可能被模型误用，
规则与评测需要继续验证，不宣称全部自然语言冲突都能自动识别。

验证应分别覆盖以下行为，并以本轮实际报告为准：

- 跨会话读取、修改后生效、禁用/本次不使用、删除后的有效条目与旧历史保留。
- 当前要求覆盖长期偏好，长期描述不冒充动态查询证据或用户已订核验。
- 最新原话依据、提议待批准、拒绝、重复提议/批准、旧 revision 与失效保存卡。
- 执行中设置变更拒绝，档案写入与新 run 接受的协调边界。
- 真正进程退出后的提议效果复用、批准状态和 schema 迁移；SQLite 与 PostgreSQL 分开报告。
- 公开界面及 SSE 可恢复状态，原始引用、推理和凭据的公开边界。

统一suite v2026-10-11-v3的七个离线场景完成，可判定结构化断言无失败；脚本模式的Agent

## 应用接口

以下均为当前本地单用户接口，owner 由服务端固定；请求不能选择其他用户身份。
偏好管理不直接暴露为供应商 `/tools/{name}/call` 接口。

| 接口 | 用途与边界 |
| --- | --- |
| `GET /preferences` | 管理面读取已存档案、全局开关及 revision，包括关闭后保留的条目 |
| `PUT /preferences` | 用 base_revision、upsert、remove_ids 和可选 enabled 保存用户手动变更 |
| `DELETE /preferences?base_revision=N` | 清空当前长期档案；保留全局开关与完整聊天历史 |
| `GET /conversations/{id}/preferences` | 查看该会话的本次使用开关 |
| `PUT /conversations/{id}/preferences` | 设置 use_saved；执行中拒绝更改该会话设置 |
| `GET /conversations/{id}/preference-proposals` | 读取该会话当前待用户审阅的提议 |
| `POST /conversations/{id}/preference-proposals/{proposal_id}/apply` | 带 base_revision 批准提议，校验会话归属、状态与档案版本 |
| `POST /conversations/{id}/preference-proposals/{proposal_id}/dismiss` | 拒绝指定待保存卡，不改变档案 |

创建会话可通过 `use_saved_preferences` 指定本次是否使用，默认允许；全局关闭仍会阻止
模型读取有效条目。接口语法、StrictModel 校验和实际错误码以实现为准，当前说明不代表
已经验证了所有异常路径。
